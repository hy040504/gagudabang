# 가구다방 디자인 시스템

화면에 쓰는 색, 글자, 간격, 모양을 한 곳에서 정하고 그 값만 쓰기 위한 문서다. 2026-11-27에 전체를 다시 짰다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `public/styles/tokens.css` | 토큰(값). 색, 글자, 간격, 크기, 모서리, 그림자, 움직임, 층 |
| `public/styles/base.css` | 바탕과 부품. 버튼, 입력 칸, 카드, 표, 알림, 머리 줄 |
| `public/styles/customer.css` | 고객 화면 |
| `public/styles/admin.css` | 관리자 화면 |
| `tests/tokens.test.ts` | 색 짝의 대비 검사 (밝은 화면, 어두운 화면) |

규칙은 세 가지다.

1. 값은 `tokens.css`에서만 정한다. 다른 CSS 파일에 색 코드나 px 간격을 직접 적지 않는다.
2. 화면 코드(`src/client`)에 `style="…"`을 적지 않는다. 필요한 모양은 클래스로 만든다. 예외는 사용자가 고른 데이터 값뿐이다(직접 추가한 일정의 점 색 `--k`, 차트 막대 길이).
3. 색 토큰을 바꾸거나 더하면 `npm test`로 대비 검사를 통과시킨다.

CSS는 `@layer base, components, views` 순서로 쌓인다. 뒤의 층이 앞의 층을 이기므로, 화면별 스타일이 부품을 고칠 때 `!important`나 긴 선택자가 필요 없다.

## 고치기 전의 문제 (비평)

| 문제 | 고친 내용 |
| --- | --- |
| CSS 클래스의 약 70%가 어느 화면에서도 쓰이지 않았다(초기 시연 화면의 흔적). 네 파일 3,781줄, 102KB | 쓰는 것만 남겨 네 파일 약 480줄로 줄였다 |
| 토큰이 세 번 겹쳐 정의돼 있었다(초록 계열 → 남색 계열 → 다리 역할 토큰). 정의만 되고 쓰이지 않는 토큰 39개 | 한 번만 정의한다. 쓰이지 않는 토큰은 없다 |
| 토큰 이름이 뜻과 달랐다(`--accent-tea`, `--gd-kpi-walnut`, `--gd-bezel`) | 역할 이름으로 바꿨다(`--accent`, `--panel-bg`) |
| 글자 크기 20가지, 줄 높이 25가지, 전환 시간 15가지, 모서리 값 10가지가 섞여 있었다 | 글자 9단계, 줄 높이 3단계, 시간 3단계, 모서리 5단계 |
| 간격에 6, 10, 14, 18, 22, 26px처럼 기준 없는 값이 많았다 | 4px 단위 10단계 |
| 화면 코드에 `style="…"`이 60곳 넘게 있었고, 일정 화면은 `<style>`을 통째로 품고 있었다 | 모두 클래스로 옮겼다 |
| 입력 칸 테두리가 바탕과 1.3:1이라 칸의 경계가 잘 보이지 않았다 | `--border-control`(3:1 이상)을 새로 뒀다 |
| 입력 글자가 14px이라 iPhone에서 칸을 누르면 화면이 확대됐다 | 입력 글자를 16px로 올렸다 |
| 오류가 난 칸에 표시가 없었다(칸 아래 문구만 있었다) | 오류 칸의 테두리를 오류색으로 굵게 그린다 |
| 글자 크기가 px 고정이라 브라우저 글자 크기 설정을 따르지 않았다 | rem으로 바꿨다 |
| 버튼은 알약형, 입력 칸은 12px 모서리라 나란히 놓이면 모양이 달랐다 | 버튼과 입력 칸을 같은 12px 모서리로 맞췄다(로고의 모서리와 같은 인상) |
| 화면 제목이 본문과 같은 16px이었다(로그인, 진행 조회, 마이페이지) | 화면 제목 24~34px, 카드 제목 18px로 단계를 나눴다 |
| 진행 조회와 마이페이지의 폼이 1280px 폭으로 늘어졌다 | 읽기 좋은 폭(760px, 960px)으로 가운데에 둔다 |
| 카드에 테두리와 그림자를 함께 썼다 | 카드는 테두리만, 그림자는 떠 있는 것(알림, 대화상자, 남색 판)에만 쓴다 |
| 어두운 화면용 규칙이 부품 여기저기에 흩어져 있었다 | 어두운 화면은 토큰 값만 바뀐다. 부품에는 테마별 규칙이 없다(테마 버튼 그림 제외) |
| 테마를 고르지 않아도 처음 본 값이 저장돼, 기기 설정이 바뀌어도 따라가지 않았다 | 버튼으로 고른 값만 저장한다. 고르지 않았으면 기기 설정을 따른다 |
| 마우스를 올렸을 때의 색이 휴대폰에서 누른 뒤에도 남았다 | 올림 반응은 마우스가 있는 기기에서만 준다 |

## 토큰

### 색

화면에서는 역할 이름만 쓴다. 밝은 화면의 값은 `:root`에, 어두운 화면의 값은 `:root[data-theme="dark"]`에 같은 이름으로 있다.

| 역할 | 토큰 | 쓰는 곳 |
| --- | --- | --- |
| 면 | `--bg-app` `--bg-card` `--bg-subtle` `--bg-muted` `--bg-hover` `--bg-input` `--bg-glass` | 화면 바탕, 카드, 표 머리글, 사진 자리, 올림, 입력 칸, 머리 줄 |
| 선 | `--border` `--border-strong` `--border-control` | 구분선, 버튼 테두리, 입력 칸 테두리 |
| 글자 | `--text-1` `--text-2` `--text-3` | 제목·본문, 설명, 보조 정보 |
| 브랜드 | `--primary` `--primary-hover` `--primary-fg` `--primary-soft` | 주 버튼, 링크, 선택된 것 |
| 강조 | `--accent` `--accent-fg` | 한두 곳의 표시(홈 일정의 "기준일") |
| 상태 | `--good` `--warn` `--bad` `--bad-fg` `--info` | 오류 문구, 위험 버튼, 일정 종류 |
| 남색 판 | `--panel-*` | 홈의 일정 상자와 마무리 안내 |

색은 남색 계열 하나와 남색이 섞인 회색 계열 하나다. 갈색, 베이지, 보라는 쓰지 않는다.

### 글자

글꼴은 Pretendard 하나다. 굵기는 400, 600, 700 세 가지.

| 토큰 | 기본 크기 | 쓰는 곳 |
| --- | --- | --- |
| `--fs-micro` | 12px | 달력 칸 안의 건수, 꼬리표 |
| `--fs-caption` | 13px | 도움말, 오류 문구, 표 머리글 |
| `--fs-label` | 14px | 입력 칸 이름, 작은 버튼, 관리자 본문 |
| `--fs-body` | 16px | 고객 화면 본문, 입력 값 |
| `--fs-title` | 18px | 카드 제목, 큰 버튼 |
| `--fs-heading` | 20px | 관리자 화면 제목 |
| `--fs-h2` | 22~30px | 홈 영역 제목 |
| `--fs-h1` | 24~34px | 화면 제목 |
| `--fs-display` | 32~52px | 홈 첫 화면 |

줄 높이는 `--lh-tight`(1.25, 큰 제목), `--lh-snug`(1.4, 작은 제목), `--lh-normal`(1.6, 본문). 20px 이상의 제목에는 `--tracking-tight`(-0.02em)를 준다.

### 간격과 크기

- 간격: `--space-1`(4) `2`(8) `3`(12) `4`(16) `5`(20) `6`(24) `8`(32) `10`(40) `12`(48) `16`(64). 이 밖의 값은 쓰지 않는다.
- 화면 여백: `--gutter`(16~24), 홈 영역 위아래 `--section-y`(48~80), 본문 폭 `--container`(1280), 폼 폭 `--container-form`(760), 로그인 폭 `--container-narrow`(460).
- 누르는 것의 높이: `--control-sm`(36) `--control-md`(40) `--control-lg`(52). 손가락으로 누르는 화면에서는 `--control-touch`(44) 이상.
- 모서리: `--radius-sm`(8, 사진·달력 칸) `--radius-md`(12, 버튼·입력 칸) `--radius-lg`(16, 카드) `--radius-xl`(20, 큰 판·큰 사진) `--radius-full`(점, 날짜 표시).
- 그림자: `--shadow-raised`(남색 판), `--shadow-overlay`(알림, 대화상자).
- 움직임: `--dur-fast`(120ms, 색·누름) `--dur-base`(200ms) `--dur-slow`(480ms, 처음 한 번 나타날 때), 곡선은 `--ease-out` 하나. 움직임을 줄이도록 설정한 기기에서는 세 시간이 모두 0이 된다.
- 층: `--z-sticky`(10) `--z-nav`(20) `--z-toast`(30).

### 차트 색

`--chart-1`(파랑)과 `--chart-2`(주황)는 두 계열을 나눌 때, `--chart-ord-1`~`4`는 순서가 있는 단계(품목 상태: 접수대기 → 처리완료)에, `--chart-muted`는 그 밖의 값(취소, 미정)에 쓴다. 밝은 화면과 어두운 화면 모두 색각 이상 구분, 바탕 대비, 단계 밝기 차이를 dataviz 스킬의 검사 스크립트로 확인했다. 밝은 화면의 주황은 바탕 대비가 2.9:1이라, 차트마다 범례와 "표로 보기"를 꼭 둔다. 상태색(`--good`, `--bad`)은 차트 계열에 쓰지 않는다.

## 부품

| 부품 | 클래스 | 규칙 |
| --- | --- | --- |
| 버튼 | `.btn` + `primary` `ghost` `danger` + `sm` `lg` `block` | 화면에 주 버튼은 하나. 기본은 흰 면에 테두리 |
| 입력 | `.field` 안에 `label`과 입력. `.inp`는 화면 코드가 붙인다 | 도움말은 `.field > p`, 오류는 `.err-msg`(자동) |
| 확인란 | `label.check` | 한 줄 전체가 눌린다 |
| 카드 | `.card`, 제목은 `.card-title` | 카드 안에 카드를 넣지 않는다 |
| 화면 제목 | `.page-title` | 화면에 하나 |
| 표 | `.tbl-wrap > .tbl`, 숫자 칸은 `.num` | 숫자는 `.tabular`로 자릿수를 맞춘다 |
| 사진 줄 | `.gd-photo-row` | 크기는 `--photo`로 바꾼다 |
| 알림 | `toast()` | 오류만 오류색 |
| 상태 뱃지 | `.st.st-<상태>` (관리자 접수 목록) | 글자는 상태의 의미 색, 바탕은 같은 색 8%. 접수대기 `--warn`, 진행중 `--info`, 반출예정 `--primary`, 처리완료 `--good`, 취소·반려 `--text-3`. 밝은 화면 최저 대비 4.57:1(접수대기). 바탕을 더 진하게 하면 4.5:1 아래로 떨어진다 |
| 확인 창 | `confirmDialog()` | 브라우저 기본 `confirm()` 대신 쓴다 |
| 아이콘 버튼 | `.btn` 안에 `<svg ${ICON_ATTRS}>` | 선 아이콘 규격은 `ui.ts`의 `ICON_ATTRS`(24 기준, 20px, 선 1.6) 하나다. 글자가 없으면 `aria-label`과 `title`을 붙이고, 누르는 영역은 44px 이상(사진 창의 `<` `>`) |

화면이 바뀌는 폭은 40rem(640), 48rem(768), 64rem(1024) 세 가지다.

## 브라우저

`light-dark()`는 쓰지 않는다. 2024년에 나온 기능이라 Edge·Chrome 122 이하에서는 색이 통째로 빠진다(이 프로젝트를 점검하는 PC의 Edge 120에서 실제로 빠졌다). 같은 이유로 대화상자 뒤를 가리는 막은 `::backdrop`이 아니라 대화상자의 그림자로 그린다.

## 참고한 기준

프로젝트의 `.claude/skills/`에 설치한 세 스킬을 기준으로 삼았다(저장소에는 올리지 않는다).

- Modern Web Guidance (Chrome, Edge, Firefox, MDN): 토큰 단계, `@layer`, rem 글자 크기, 대비, 테마 전환
- UI UX Pro Max: 색·글자·간격 점검 항목, 누르는 영역, 상태별 대비
- Taste Skill: 버튼 한 쌍, 카드 한 종류, 모서리 한 체계, 좌우 같은 가장자리
