### DEPLOY-01 Vercel 배포 — 완료(시연용)

- 배포(2026-11-27): Vercel 프로젝트 `gagudabang`에 올렸고 주소는 `https://gagudabang.vercel.app`이다. 환경 변수 두 개는 Production에만 넣었다(값은 로컬 `.env`에 보관, 저장소에는 올리지 않는다). 저장소와 자동 연결은 하지 않아서, 다시 배포하려면 `npx vercel deploy --prod`를 실행한다.
- 첫 화면(`/`)은 `vercel.json`의 `routes`가 `public/index.html`로 이어 준다. `rewrites`로는 이어지지 않고 요청이 함수로 넘어가서 `routes`를 썼다.

### 관리자 화면 보강 (2026-11-27)
- 통계 오류: 개인 서버 주소에서 Cloudflare가 화면 파일(JS·CSS)을 "브라우저에 4시간 저장"으로 바꿔 내보내, 전에 관리자 화면을 열었던 브라우저가 예전 통계 코드로 새 통계 API를 읽다 멈췄다. Cloudflare에 `gagudabang.mib.dpdns.org`에만 적용되는 캐시 규칙(브라우저 저장 시간은 서버 헤더를 따른다)을 넣었고, 서비스 워커는 화면 파일을 가져올 때 매번 서버에 최신인지 묻는다. 같은 영역의 다른 주소와 영역 전체 설정은 바꾸지 않았다.
- 사고와 조치(2026-11-27): 처음 넣은 Cloudflare 규칙(브라우저 저장 시간만 지정)이 이 주소의 응답을 Cloudflare에 저장 가능하게 만들어, 약 1시간 동안 관리자 API 응답(접수 목록·통계·일정, 예시 데이터와 점검용 접수 1건)이 로그인하지 않은 요청에도 저장본으로 나갔다. 규칙을 'Cloudflare 저장 안 함 + 브라우저 저장 시간은 서버 헤더'로 바꾸고 이 주소의 저장본을 모두 지웠다. 서버는 이제 모든 API 응답에 `Cache-Control: no-store`를 붙인다(사진은 `private`). 실제 고객 데이터는 아직 없었다.
- 일정: 직접 추가하는 일정에 점 색을 고를 수 있다(기본 회색, 7가지, 직접 고르기). 서버는 `#rrggbb`만 받는다(`custom_events.color`). 이 색은 화면에 `style="--k:색"`으로 들어가는 유일한 인라인 스타일이다.
- 확인 창: 브라우저 기본 `confirm()` 대신 화면과 같은 디자인의 확인 창(`confirmDialog`, `src/client/common/ui.ts`)을 쓴다. 일정 삭제, 문자 보내기, 고객 신청 취소(진행 조회·마이페이지)에 쓴다.
- CSV: 상단 바의 CSV 버튼을 빼고 통계 화면의 "접수 목록 CSV 내려받기"로 옮겼다(전체 접수).
- 접수 목록: 상태·처리 구분은 고르면 바로 걸러진다. 가구마다 첫 사진이 작게 보이고, 누르면 그 가구의 사진을 크게 넘겨 본다(상세 화면과 같은 창).

  - "품목 상태" 칸을 "품목"과 "상태"로 나눴다. 상태는 품목마다 뱃지(`.st`, 의미 색 글자에 옅은 바탕)로 보이고, 두 칸의 줄이 맞도록 품목 이름은 꺾지 않는다.
  - 처리 구분 첫 항목은 "전체"로 바꿨다.
  - 관리자 상단 로고는 관리자 홈(접수 목록) 링크다. 누르면 거르기와 쪽을 처음으로 되돌린다.
  - 고객 상단 버튼은 "+ 가구 접수"로 바꿨다.

- 화면이 바뀌면 같은 스크립트로 그림을 다시 찍고 `scripts/guide/build-pdf.mjs`로 PDF를 다시 만든다.

### 추가 확인 (2026-11-27)
- 설치 파일을 조용히 설치해 실행하고(관리자 화면 열림) 제거까지 해 봤다. 남은 파일과 바로 가기는 없었다.
- 배포된 주소를 아이폰 환경(WebKit, 터치, 390x844)으로 열어 일곱 화면과 관리자 로그인 화면에 가로 넘침과 오류가 없음을 봤다. 공유 정보와 대표 그림도 배포 주소에서 내려온다. 실제 휴대폰과 메신저에서 보이는 모습은 확인하지 못했다.
- 배포 직후 한 번, 가입한 계정으로 로그인이 실패했다. 서버가 동시에 여러 대 뜨면 서로 다른 임시 데이터를 보기 때문이다. 데이터를 보관하는 구성으로 바꾸기 전까지는 다시 생길 수 있다.

### 직접 운영 서버 (2026-11-27)
- Vercel과 별도로, 개인 서버(Ubuntu, Node 24)에 저장소를 복제해 실행 중이다. 서버 안의 `~/gagudabang`, 5020번 포트(서버 안에서만 접속), `start.sh`로 켜고 재부팅하면 자동으로 다시 켜진다(crontab). 환경 변수는 서버의 `.env`에 있다.
- 이 서버에서는 접수 데이터와 사진이 `data/` 폴더에 남는다. Vercel의 "데이터가 지워지는 문제"가 없다.
- 주소: `https://gagudabang.mib.dpdns.org` (관리자 화면은 `/admin`). Cloudflare 터널에 이 호스트 이름을 추가해 5020번 포트로 이었다(2026-11-27).
- 관리자 화면 주소를 `/admin.html`에서 `/admin`으로 바꿨다. 예전 주소로 오면 새 주소로 넘긴다. Vercel과 개인 서버 모두 같다.
- 남은 것: `public/index.html`과 `public/admin.html`의 공유 정보 주소는 아직 Vercel 주소다. 어느 주소를 대표로 쓸지 정해지면 맞춘다.
- 코드를 고친 뒤 서버에 반영하려면: `git pull && npm ci && npm run build && ./start.sh`.

### 관리자 추가 기능 (2026-11-27)
- 일정 화면에서 날짜를 고른 뒤 접수와 상관없는 일정을 직접 추가하고 지울 수 있다(`custom_events` 표, 달력에는 "직접 추가" 점으로 표시).
- 통계 메뉴가 생겼다: 접수·가구·회원·보낸 문자 합계, 상태별·처리 구분별·가구 종류별 수와 비율, 최근 6개월 월별 접수. 표로만 보여 준다. (같은 날 뒤에 기간 선택과 차트로 바꿨다. 아래 "예시 데이터, 통계 화면" 참고)
- 상단 바: 테마 버튼을 달·해 아이콘으로, 로그아웃을 CSV와 같은 모양으로 바꿨다. 640px 이하에서는 CSV, 테마, 로그아웃이 로고 아래 줄 오른쪽에 모인다. (같은 날 뒤에 CSV는 통계 화면으로 옮겼다) 하단 탭은 네 개(접수 목록, 일정, 통계, 설정)가 됐다.
- 홈 사진을 한국 아파트 거실에서 두 사람이 소파를 옮기는 그림으로 바꿨다. 무료 사진 사이트에서는 맞는 사진을 찾지 못해 사용자 승인을 받고 AI(Figma 이미지 생성)로 만들었다. 실제 인물이 아니다. 고객용 공유 그림에도 같은 그림을 쓴다.

### 테스트 계정과 디자인 점검 (2026-11-27)
- 테스트용 회원 계정이 서버가 뜰 때 자동으로 만들어진다: 아이디 `abcd`, 비밀번호 `1234`(이름·연락처·주소는 지어낸 예시). 누구나 아는 약한 비밀번호라 실제 고객을 받기 전에 `src/server/index.ts`와 `src/index.ts`의 `testAccount: true`를 빼야 한다.
- 디자인 점검 결과는 루트의 `DESIGN_AUDIT.md`에 있다. 작은 글씨(입력 칸 이름 12.5px 등), 휴대폰의 작은 누름 영역, 어두운 화면의 버튼 대비, 좁은 화면 표의 줄 끊김을 고쳤고, 글자 크기·굵기·반지름·간격 값을 기준 단계로 정리했다. 기능은 바꾸지 않았다.

### 알려진 사항
- 미확정 사업자 정보는 빈칸으로 두고 고객 화면에 표시하지 않는다(관리자 설정에서 입력).
- 예시 데이터(`is_demo = 1`)가 두 배포에 들어 있다. 실제 운영 전에 `npm run demo:clear`로 지우고 `DEMO_DATA=0`으로 끈다.
- 저장소에 올리기 전에는 추가된 내용을 검사한다(이메일, 전화번호, 사업자번호, 실명, 비밀값, 로컬 경로). 올리지 않는 것: 견적서, 일부 설계 SVG와 PDF, `demo.html`, `demo/`, `CLAUDE_KO.md`, `CLAUDE_EN.md`, `.env*`, `data/`.
- 프로젝트 전체에 소리를 내거나 글을 읽어 주는 기능은 없다.
- 운영 환경(NODE_ENV=production)에서는 ADMIN_PASSWORD와 SESSION_SECRET이 없으면 서버가 뜨지 않는다. 로컬 개발에서는 기본값으로 동작한다.
