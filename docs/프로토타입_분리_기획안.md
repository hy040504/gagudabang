# 프로토타입 분리 기획안 (2단계: 관리자 웹 구성요소)

- 작성일: 2026-11-26
- 대상 산출물: `prototype/customer.html`, `prototype/admin.html`, `prototype/tokens.css`, `prototype/data.js`
- 전제(1단계에서 제안, 2단계 진행으로 확정 간주): 대상은 이사를 앞둔 개인 고객(주로 스마트폰)과 운영자(주로 데스크톱), 목적은 가구 접수와 진행 조회, 톤은 "차분하고 믿음직한" 하나.

## 2. 우리 서비스에 넣는 것

운영 규모는 운영자 1~2명, 하루 접수는 소량이고, 일의 핵심은 "이사일 전에 품목별로 판매·반출을 끝내는 것"이다.

| 넣는 것 | 내용 | 근거 |
| --- | --- | --- |
| 메뉴 5개 | 오늘, 접수, 일정, 안내 관리, 설정. 1440px은 사이드 메뉴, 768px은 아이콘 레일, 390px은 하단 탭. | 목적지가 5개 이하라 하단 탭에 들어간다(Android 가이드). 깊이 1단계(AdminLTE). |
| 오늘(첫 화면) | 지표 4개(접수대기 품목, 이사일 3일 이내, 판매 마감 임박·경과, 7일 내 반출 예정)와 "급한 순 접수" 목록. 지표를 누르면 그 조건의 목록으로 이동. | 지표는 위에(AdminLTE). 실제 앱의 KPI 4종과 같다. |
| 접수 목록 | 상태 필터, 검색, 이사일 임박순 정렬, 행을 누르면 상세. 접수 추가(전화 접수 대응)와 삭제. | Polaris 목록 구성. NN/g 과업 1·3번. |
| 접수 상세 | 신청자·수거지, 품목별 상태 변경(기존 상태 전이 규칙 유지), 판매 마감일, 확정 반출 일정, 고객 공개 안내문, 내부 메모, 변경 이력. | NN/g 과업 3번. 변경 이력이 감사 로그의 최소형. |
| 일정 | 달력에 이사일·판매 마감·반출을 세 가지 표시(색과 글자를 같이 씀)로 보여 주고, 날짜를 누르면 그날 일정. | 서비스의 핵심이 날짜 역산이다. 색만으로는 구분하지 않는다. |
| 안내 관리 | 자주 묻는 질문과 공지사항을 각각 추가·수정·삭제. 자주 묻는 질문은 고객 홈에, 공지사항은 고객 화면의 공지 영역에 바로 반영. | 운영자가 쓰는 콘텐츠 기능은 따로 필요(위시켓). 공지사항은 사용자 결정으로 포함(2026-11-26). |
| 설정 | 사업자 정보(고객 푸터에 반영), 샘플 데이터 초기화. | 실제 앱의 설정과 같다. |
| 빈 상태 | 목록마다 "왜 비었는지"와 다음 행동 버튼. 검색 결과 없음과 구분. | NN/g. |
| 상태 색 | 접수대기·진행중·반출예정·처리완료·취소 다섯 가지에만 색을 쓴다. | AdminLTE. |

## 3. 넣지 않는 것

| 뺀 것 | 이유 |
| --- | --- |
| 추세 차트, 이전 기간 대비 | 지표가 "지금 처리할 건수"라 증감이 판단에 쓰이지 않는다. 데이터도 적다. |
| 일괄 작업 | 품목마다 상태와 날짜를 따로 판단해야 하고 건수가 적다. |
| 계정·권한 관리 | 운영자가 1~2명이고 실제 앱도 관리자 계정 하나다. |
| 알림 센터, 전체 검색 | 첫 화면의 급한 순 목록과 접수 목록 검색으로 충분하다. |
| CSV 내보내기 | 실제 앱에는 있지만 정적 프로토타입에서는 다루지 않는다. |

## 4. 데이터와 두 웹의 연결

- `data.js` 한 파일에 샘플 데이터를 두고, 화면에는 "샘플" 표시를 붙인다. 접수(신청자, 수거지, 이사일, 품목 목록), 자주 묻는 질문, 공지사항, 사업자 정보, 가구 종류.
- 처음 열 때 샘플을 `localStorage`에 넣고, 이후 추가·수정·삭제는 `localStorage`에서 한다. 설정의 "샘플 데이터 초기화"로 되돌린다.
- 관리자 → 고객 반영: 접수 상태·날짜·안내문은 고객의 진행 조회에, 자주 묻는 질문은 고객 홈에, 공지사항은 고객 화면의 공지 영역에, 사업자 정보는 고객 푸터에 나타난다.
- 고객 → 관리자 반영: 고객이 접수하면 관리자 접수 목록과 오늘 화면에 나타난다. 다른 탭에서 바뀐 내용은 `storage` 이벤트로 다시 그린다.

### 4단계 재확인 (2026-11-26)

처음에 건너뛴 확인을 다시 했다. Hallmark 점검 도구의 화면 렌더링 검사와 별도 검토(마무리 검토)에서 나온 것을 고쳤다.

| 나온 문제 | 고친 내용 |
| --- | --- |
| 건너뛰기 링크가 포커스를 받아도 보이지 않음 | 포커스를 받으면 화면 위에 나타난다. 누르면 주소를 바꾸지 않고 본문으로 초점만 옮긴다. |
| 사진 출처 링크가 좁은 화면에서 여러 줄로 꺾임 | 제목은 글로 두고 링크는 "원본" 한 낱말로 줄였다. |
| 섹션 제목이 첫 화면 제목에 비해 작음 | 1440px에서 40px이 되도록 키웠다. |
| 첫 화면 아래에 빈 띠가 김 | 사진을 5:4로 키우고 아래 여백을 줄였다. |
| 일정 줄이 "1단계, 2단계" 설명 네 칸이라 "거꾸로"가 보이지 않음 | 선 하나에 점 네 개인 타임라인으로 바꿨다. 선은 큰 남색 점(이사일)에서 끝난다. 좁은 화면에서는 세로로 선다. |
| 섹션마다 같은 선과 같은 간격 | 일정은 옅은 면, 가구 종류는 여백, 공지와 질문은 선, 마무리는 남색 면으로 구분하고 간격도 다르게 했다. |
| 가구 종류가 가장 큰 영역인데 누를 수 없음 | 한 줄 여섯 칸으로 줄이고, 누르면 그 종류가 선택된 접수 화면으로 간다. |
| 첫 화면 사진이 어둡고 사람이 누워 있음 | 햇빛이 드는 거실 사진으로 바꾸고 설명 글도 맞췄다. |
| "옷장·수납"의 가운뎃점 | "옷장과 수납장"으로 바꿨다. |

받아들이지 않은 제안: 일정 줄에 샘플 접수의 실제 날짜를 넣자는 제안. 고객 한 명의 접수가 홈에 보이게 되고, 날짜 간격을 정한 규칙이 없어 지어낸 숫자가 되기 때문이다.

## 8. 5단계 결과 (관리자 웹)

- 파일: `prototype/admin.html`, `admin.css`, `admin.js`. 공용 `ui.css`, `store.js`, `data.js`, `tokens.css`, `base.css`를 그대로 쓴다.
- 화면 다섯 개와 주소:

| 메뉴 | 주소 | 내용 |
| --- | --- | --- |
| 오늘 | `#today` | 지표 네 개(누르면 그 조건의 접수 목록)와 이사일이 가까운 순서로 선 접수 줄 |
| 접수 | `#apps`, `#apps?f=조건&q=검색어` | 조건과 검색, 표(좁은 화면에서는 줄마다 묶음), 접수 추가 |
| 접수 상세 | `#apps/접수ID` | 품목별 상태·판매 마감일·확정 반출 일시·고객 안내문, 내부 메모, 변경 이력, 정보 수정, 삭제 |
| 접수 추가·수정 | `#apps/new`, `#apps/접수ID/edit` | 신청자, 수거 장소와 일정, 품목(추가·삭제) |
| 일정 | `#schedule?m=연-월&d=날짜` | 달력에 이사일·판매 마감·반출 표시, 날짜를 누르면 그날 일정 |
| 안내 관리 | `#content/faq`, `#content/notice` | 자주 묻는 질문과 공지사항의 추가·수정·삭제 |
| 설정 | `#settings` | 사업자 정보, 샘플 데이터로 되돌리기 |

- 화면 폭에 따른 메뉴: 1440px은 왼쪽 사이드 메뉴, 768px은 아이콘과 이름이 세로로 놓인 레일, 390px은 상단 바와 하단 탭 다섯 개.
- 규칙: 상태 변경은 실서버(`src/shared/types.ts`의 `TRANSITIONS`)와 같다. 반출예정은 확정 반출 일시가, 취소는 사유(고객 안내문)가 있어야 저장된다. 판매 마감일은 이사일보다 늦을 수 없다. 삭제와 초기화는 한 번 더 묻는다.
- 두 웹의 연결: 관리자가 저장하면 고객 웹의 진행 조회, 홈의 공지와 질문, 푸터의 사업자 정보가 새로 고침 없이 바뀐다. 고객이 접수하면 관리자의 오늘 화면과 접수 목록에 나타난다. 다른 탭에서 데이터가 바뀌어도 입력 중인 폼은 지워지지 않는다.
- 데이터에 추가된 것: 접수에 `history`(상태 변경 이력, 관리자 화면에서만 보임).
- 넣지 않은 것: 불러오는 중 표시(데이터가 브라우저 안에 있어 바로 읽힌다), 삭제 되돌리기(대신 한 번 더 묻는다), 질문 순서 바꾸기, 관리자 로그인(정적 프로토타입이라 누구나 열 수 있다).
- 여는 방법: Chrome이나 Edge에서 `prototype/admin.html`과 `prototype/customer.html`을 더블클릭해 열면 된다(두 탭의 데이터가 이어진다). 서버로 열 때는 두 화면을 같은 주소와 같은 포트로 연다.

### 별도 검토에서 나와 고친 것 (2026-11-26)

| 나온 문제 | 고친 내용 |
| --- | --- |
| 삭제 확인을 열거나 닫으면 쓰던 내용이 사라짐 | 화면을 다시 그리지 않고 확인 줄만 보이고 숨긴다. 초점은 "돌아가기"에 둔다. 저장하지 않은 입력이 있으면 다른 탭의 변경으로도 화면을 다시 그리지 않는다(고객 웹도 같다). |
| 좁은 화면에서 "변경 저장"이 맨 아래에 있음 | 저장 줄을 화면 아래에 붙이고, 고친 내용이 있으면 "저장하지 않은 변경이 있습니다."를 보여 준다. |
| 접수 상세의 제목이 접수번호라 남은 날이 묻힘 | 제목을 "D-9 이름"으로 바꾸고 접수번호, 날짜, 전화 링크를 그 아래 한 줄에 뒀다. |
| 오늘 화면에서 지표 숫자가 남은 날보다 큼 | 두 크기를 바꿨다. 가장 큰 숫자는 이사일까지 남은 날이다. |
| 좁은 화면의 접수 목록이 이름표 다섯 줄 묶음 | 오늘 화면의 접수 줄과 같은 모양으로 줄였다. 접수번호와 접수일은 상세에서 본다. |
| 삭제 버튼이 평소에도 빨간색 | 평소에는 본문색이고 "삭제 확정"만 빨간색이다. |
| 달력에서 선택 표시가 포커스 테두리를 가림 | 선택 표시를 안쪽 그림자로 바꿨다. 좁은 화면에서는 칸 높이를 줄여 그날 일정이 바로 보인다. |
| 좁은 화면의 버튼이 40px이고 상단 바가 계속 따라옴 | 좁은 화면에서는 48px을 쓰고, 상단 바는 스크롤하면 올라간다. |

## 9. 6단계 결과 (마무리 점검)

### 깨짐 점검 (break-ui)

- 점검용 데이터는 `data.js`의 `GD_FIXTURES`에 있다. 주소 끝에 `?data=worst`(가장 긴 값), `?data=empty`(빈 목록), `?data=one`(하나씩), `?data=huge`(접수 1,284건)를 붙이면 그 데이터로 열리고, 화면 아래에 전환 막대가 나온다. 평소 주소에서는 막대가 나오지 않고, 저장 칸이 달라 평소 데이터와 섞이지 않는다.
- 길이는 입력 칸이 받는 최대 길이에 맞췄다(이름 50, 품목명 60, 주소 200, 안내문 500, 제목 80). 한 접수에 품목 20개, 다섯 상태가 한꺼번에, 이사일이 128일 지난 접수와 365일 남은 접수, 없는 사진 파일, 태그 문자가 들어간 제목도 넣었다.

| 나온 문제 | 고친 내용 |
| --- | --- |
| 띄어쓰기 없는 긴 이름·품목명·링크가 칸 밖으로 잘림(고객 홈, 진행 조회, 관리자 오늘·목록·상세·일정·안내 관리) | 칸을 넘기 전에 줄을 바꾸도록 했다. 접수번호와 전화번호는 통째로 다음 줄로 넘긴다. |
| 접수 1,284건을 한 번에 그려 검색 입력이 한 글자에 0.19초 걸림 | 접수 목록은 50건씩 그리고 "더 보기"로 늘린다. 오늘 화면은 가장 급한 10건만 보여 준다. 한 글자에 0.014초가 됐다. |
| 접수를 지운 뒤 같은 접수번호가 다시 나옴 | 개수가 아니라 가장 큰 번호 다음 번호를 쓴다. |
| 다른 해의 날짜에 연도가 없어 올해처럼 읽힘 | 올해가 아니면 연도를 붙인다(예: 2027년 1월 25일). |
| 여러 줄로 쓴 안내문·공지·답변의 줄바꿈이 사라짐 | 줄바꿈을 그대로 보여 준다. |
| 저장 공간이 가득 차면 아무 말 없이 저장이 안 됨 | 저장하지 못했다고 화면에 알린다. |
| "D+128"이 자기 칸보다 넓음, 320px에서 관리자 상단 바 글자가 겹침, 768px 표에서 이름이 한 글자씩 끊김 | 칸 폭을 넓히고, 아주 좁은 폭에서는 "고객 화면" 글자를 숨기고, 표의 이름 칸에 최소 폭을 주고 접수일 칸을 접었다. |

견딘 것: 빈 목록 안내(모든 목록에 있음), 태그 문자가 글자 그대로 보임, 이모지와 오른쪽에서 왼쪽으로 쓰는 이름, 없는 사진(빈 칸으로 남음), 다크 모드, 글자 크기 2배.

사용자가 정한 것(2026-11-26): 고객 홈의 질문은 5개까지 보이고 나머지는 "질문 N개 더 보기"로 접는다. 공지사항은 고객 화면과 관리자 목록 모두 20건씩 보이고 "더 보기"로 늘린다. 게시일이 미래인 공지는 그날부터 고객 화면에 보이고, 관리자 목록에는 "게시 예정"으로 표시된다.

### 접근성과 웹 지침 점검 (web-design-guidelines)

고친 것: 오류 문구를 입력칸과 연결, 키보드 초점이 하단 탭이나 저장 줄에 가리지 않게 함, 저장하지 않은 입력이 있으면 화면을 떠나기 전에 물음, 전화번호 칸 종류와 자동 완성 속성, 좁은 화면의 작은 버튼 44px, 따옴표 모양, 날짜를 `Intl.DateTimeFormat`으로, 주소창 색을 화면 바탕색에 맞춤, 누를 때 지연 없애기, 저장 버튼 이름을 구체적으로, 탭에 마우스를 올렸을 때 표시.

남긴 것: 표의 행을 눌러 상세로 가는 동작은 스크립트로만 된다(이름 링크가 같은 일을 한다). 글꼴 미리 불러오기는 넣지 않았다(파일로 직접 열 때 경고가 나고 글꼴 파일이 크다). 색이 바뀌는 전환 효과는 그대로 뒀다(짧고, 움직임 줄이기 설정을 따른다). 고객 공지와 질문 목록은 건수 제한이 없다(위의 "정해 주면 고칠 것").

### 콘솔 오류 점검 (chrome-devtools)

추가 확인(2026-11-27): Firefox 159에서 파일로 직접 연 두 화면이 데이터를 함께 쓰고 오류가 없다. 접근성 자동 검사(axe-core)를 밝은 화면·어두운 화면, 1280px·390px의 48개 화면 상태에 돌렸고, 달력 날짜 링크의 읽는 이름 1종만 나와 고쳤다. 화면 낭독기로 직접 듣는 확인은 하지 않았다.

실제 Chrome에서 두 화면의 모든 주소를 돌며 폼 제출, 삭제 확인, 테마 전환까지 눌렀다. 서버로 연 경우와 파일로 직접 연 경우 모두 오류와 경고가 없다. 처음에 관리자 화면에서 "자동 완성 속성 없음" 알림이 1건 나와 고쳤다. `?data=worst`에서는 일부러 넣은 없는 사진 때문에 404가 1건 나온다.

## 10. 로고와 원본 데모 분리 (2026-11-27)

### 로고

- 원본은 남색 글자에 바탕이 없는 "가구다방" 글자 로고다. 바탕과 글자 색을 뒤집어 남색 바탕에 흰 글자로 만들었고, 남색은 화면의 주색(`#14284b`), 흰색은 `#ffffff`로 맞췄다.
- 글자 로고라 32px 정사각형으로는 읽히지 않는다. 그래서 글자 영역만 잘라 두 가지로 만들었다: 가로형 `logo.svg`(상단 바에 쓴다)와 정사각형 `icon.svg`(브라우저 탭 아이콘, 관리자 레일에 쓴다).
- 적용한 곳: 프로토타입(`prototype/assets/`), 실제 앱(`public/assets/brand/`, 고객 헤더와 관리자 화면), 문서용 아이콘(`docs/assets/brand/icon.svg`), 나눈 데모. 로고 그림에 이름이 들어 있어 옆에 따로 쓰던 "가구다방" 글자는 뺐다.

### 원본 데모(demo.html) 분리

- `demo.html`은 고객 화면, 관리자 화면, 기기 뷰어가 한 파일에 있다. 이것을 `demo/customer.html`과 `demo/admin.html`로 나눴다. 원본은 그대로 뒀다.
- 나누는 일은 `scripts/split-demo.mjs`가 한다(`node scripts/split-demo.mjs`). 함수 217개가 어느 화면에서 쓰이는지 따라가 공용 41개(`demo/shared.js`), 고객 전용 91개(`demo/customer.js`), 관리자 전용 73개(`demo/admin.js`)로 나누고, 기기 뷰어 전용 10개는 뺐다. 스타일은 `demo/shared.css`다.
- 두 파일은 같은 저장 칸을 써서 데이터가 이어진다. 다른 화면의 주소로 가려 하면 그 파일로 넘어간다.
- `demo/` 폴더는 원본과 같은 시연 데이터가 들어 있어 저장소에 올리지 않는다(`.gitignore`).

### 6단계 변경분의 별도 검토 (2026-11-27)

별도 검토자가 6건을 지적했고 모두 고쳤다: 질문을 펼치면 왼쪽이 비던 것(공지 목록을 화면에 붙임), "더 보기"가 질문처럼 보이던 것(버튼 모양으로 바꾸고 펼치면 "접기"), 관리자 공지의 게시 예정 표시(상태 표시로 바꾸고 긴 내용은 세 줄까지), 긴 질문의 세모 표시 위치, "더 보기"를 누른 뒤 초점(새로 나온 첫 줄로 이동), 레일의 정사각 로고 크기(56px).

### 추가 확인과 사진 교체 (2026-11-27)

- 가구 사진 7장을 Pexels의 무료 이용 사진으로 바꿨다(밝은 실내, 사람 없음, 960x720, 촬영 정보 없음). 출처는 `prototype/assets/photos/credits.js`와 고객 화면 푸터에 있다.
- 나눈 데모의 세부 동작을 원본과 같은 순서로 돌렸다: 접수, 완료, 조회, 취소, 회원 로그인과 마이페이지, 관리자 로그인, 상세의 메모와 품목 저장, 일정, 설정, 두 화면 사이의 반영. 모두 동작했다. 원본을 탭 두 개로 띄운 경우에는 관리자 메모가 저장되지 않았고, 나눈 쪽은 저장됐다(나누면서 생긴 문제가 아니라 원본의 차이다).
- 낭독기가 읽는 구조(접근성 트리)를 접수 폼, 진행 조회, 관리자 틀, 달력에서 뽑아 확인했다. 오류 문구가 칸 바로 뒤에 읽히고, 메뉴와 버튼에 이름이 있고, 달력 날짜는 "1 일, 일정 0건"으로 읽힌다. 화면 낭독기로 직접 듣는 확인은 사람이 해야 한다.
