### 서버 불변 규칙 (Invariants)
1. `admin_memo`와 `admin_item_memo`는 어떠한 고객 API(`/api/applications/lookup`, `/api/my/*`) 응답에도 포함될 수 없다.
2. 업로드 이미지(`GET /api/uploads/:storedName`)는 관리자 세션(`fr_admin`) 또는 해당 신청 건의 유효 열람 권한(본인 회원 `fr_customer` 또는 단기 조회 토큰 `fr_lookup`)이 없으면 `404 Not Found`로 응답한다.
3. 품목 상태 변경은 정의된 **상태 전이표(3.4절)** 안에서만 허용되며, 허용되지 않는 전이(예: 고객이 이미 `IN_PROGRESS`인 건을 임의 취소)는 `409 TRANSITION_DENIED`로 거부한다.
4. 관리자 품목·메모 수정 요청은 `version` 값을 함께 보내야 하며, 다른 관리자가 먼저 변경한 경우 `409 VERSION_CONFLICT`와 최신 레코드를 반환한다.
5. `status_history` 감사 로그 테이블은 `INSERT`만 허용하며 수정·삭제 API를 두지 않는다(Append-only).

## 1.3 시스템 논리 구성 및 모듈 책임

- **채널 계층 (Channel)**: ① 모바일·PC 브라우저 웹(`index.html`), ② 설치형 PWA 웹앱(`manifest.webmanifest`), ③ 운영자용 콘솔 웹 및 Electron 데스크탑 창(`admin.html` + `desktop/main.cjs`).
- **게이트웨이·미들웨어 계층 (Express Pipeline)**: 보안 헤더(`nosniff`, `SAMEORIGIN`, `CSP`), `Origin` CSRF 검증, IP·계정별 `SlidingWindowRateLimiter`, 듀얼 쿠키 파서(`fr_customer` / `fr_admin`), `Idempotency-Key` 미들웨어, `multer` 메모리 수신 후 미디어 검증기 연결.
- **도메인 서비스 계층 (Domain Services)**:
  - `AuthService`: `scrypt` 비밀번호 해싱·검증, 서명 세션 토큰 발급, 로그인 5회 실패 60초 잠금, 비회원 신청 건 회원 계정 승계(`claimGuestApplication`).
  - `ApplicationService`: 다품목 신청 원자적 생성, 접수번호(`FR-YYYYMMDD-NNN`) 채번, 비회원 4자리 PIN 검증, 고객 초기 취소 처리.
  - `MediaService`: 매직 바이트 시그니처 판별(`JPEG`/`PNG`/`WebP`), 순수 버퍼 JPEG EXIF(APP1) 제거, UUID 파일 저장 및 트랜잭션 실패 시 고아 파일 즉시 롤백 삭제.
  - `AdminWorkflowService`: 4대 운영 KPI 산출, 다중 필터·검색·정렬 목록, 월간/주간 3색 일정 캘린더 집계, 품목 상태·판매마감일·반출일 갱신(`version` 잠금 + `status_history` 기록), 수식 인젝션 방어 UTF-8 BOM CSV 생성.
- **저장소 및 외부 연계 계층 (Data & External)**: Node 내장 `node:sqlite` (`data/furni-resale.sqlite`), 로컬 격리 이미지 저장소(`data/uploads/`), 카카오(Daum) 무료 우편번호 스크립트(클라이언트 도로명 검색, 장애 시 수동 입력 폴백), 모바일 OS 네이티브 `tel:` / `sms:` 연동.

## 1.5 공통 품목 상태머신 및 D-Day 산정 규칙

신청 마스터(`applications`)는 고객·주소·이사일 정보를 담는 컨테이너이며, 실제 업무 진행 상태는 **개별 가구 품목(`application_items.status`)** 단위로 동작합니다. 신청 건 전체의 대표 요약 배지는 하위 품목들의 상태 조합으로 자동 계산됩니다.

| 상태 코드 | 한글 상태명 | 고객 진행률 | 진입 조건 | 다음 허용 상태 |
| --- | --- | :---: | --- | --- |
| `PENDING` | **접수대기** | `25%` | 고객 신청(`POST /api/applications`) 커밋 직후 기본값 | `IN_PROGRESS`, `SCHEDULED`, `CANCELED` |
| `IN_PROGRESS` | **진행중(판매·처분)** | `50%` | 운영자가 사진 검토 후 판매 대행 게시 또는 처분 조율 착수 (`판매 마감일` 지정 권장) | `SCHEDULED`, `COMPLETED`, `CANCELED` |
| `SCHEDULED` | **반출예정** | `75%` | 구매자 매칭 성사 또는 마감 후 처분 반출 확정 (`pickup_schedule` 확정 반출 일시 필수) | `IN_PROGRESS`(일정 재조정), `COMPLETED`, `CANCELED` |
| `COMPLETED` | **처리완료** | `100%` | 현장 방문 반출 및 정산·처분 종결 | 종결 상태 (전이 불가) |
| `CANCELED` | **취소·반려** | `—` | `PENDING` 단계 고객 자율 취소 또는 운영자 수거불가·현장취소 처리(`public_notice` 사유 필수) | 종결 상태 (전이 불가) |

### 일정 D-Day 경보 산정 규칙 (Asia/Seoul 자정 기준 실시간 계산)
- **이사일 임박 경보 (`movingDday`)**: 미종결(`PENDING`, `IN_PROGRESS`, `SCHEDULED`) 품목이 남아 있는 신청 건 중 `moving_date - today ≤ 3일`인 건은 `A-02` 상단 **이사일 임박 KPI** 및 적색 `D-n` 배지로 최우선 노출합니다.
- **판매 마감일 경보 (`deadlineDday`)**: `handling_type = 'RESALE'`이고 `status = 'IN_PROGRESS'`인 품목 중 `sale_deadline - today ≤ 1일`(임박) 또는 `< 0`(마감 경과)인 품목은 **처분 전환 또는 반출일 확정 대상**으로 황색/적색 강조 배지를 표시합니다.

### 핵심 테이블 및 인덱스·보존 정책 요약
| 테이블명 | 역할 | 주요 인덱스 및 제약조건 | 보존 및 수정 정책 |
| --- | --- | --- | --- |

## 3.3 핵심 서버 처리 알고리즘 규약

```typescript
// 1) 매직 바이트 시그니처 판별 및 JPEG EXIF(APP1: GPS·기기정보) 순수 버퍼 제거
function sanitizeUploadedImage(buf: Buffer): { mime: 'image/jpeg' | 'image/png' | 'image/webp'; clean: Buffer } {
  if (buf.length >= 4 && buf[0] === 0xff && buf[1] === 0xd8 && buf[2] === 0xff) {
    // JPEG 마커 순회: SOS(0xDA) 도달 전까지 APP1(0xFFE1: EXIF/XMP) 세그먼트만 제거하여 픽셀 재압축 손실 없이 GPS 원천 삭제
    return { mime: 'image/jpeg', clean: stripJpegApp1Segments(buf) };
  }
  if (buf.length >= 8 && buf.subarray(0, 8).equals(PNG_MAGIC)) {
    return { mime: 'image/png', clean: buf }; // PNG eXIf/tEXt 청크 제거 포함
  }
  if (buf.length >= 12 && buf.subarray(0, 4).toString() === 'RIFF' && buf.subarray(8, 12).toString() === 'WEBP') {
    return { mime: 'image/webp', clean: buf };
  }
  throw new AppError(415, 'UNSUPPORTED_MEDIA', '지원하지 않는 이미지 형식입니다. (JPG, PNG, WebP만 가능)');
}

// 2) 품목 상태·일정 변경 트랜잭션 (상태 전이 가드 + 낙관적 잠금 + 감사 이력 원자적 커밋)
function updateItemWorkflowTx(itemId: number, patch: AdminItemPatchDto, adminActor: string) {
  db.exec('BEGIN IMMEDIATE');
  try {
    const current = getItemById(itemId);
    if (!current) throw new AppError(404, 'NOT_FOUND', '대상 가구 품목을 찾을 수 없습니다.');
    if (current.version !== patch.version) {
      throw new AppError(409, 'VERSION_CONFLICT', '다른 관리자가 먼저 변경했습니다. 최신 상태를 확인해 주세요.');
    }
    if (!isAllowedTransition(current.status, patch.status)) {
      throw new AppError(409, 'TRANSITION_DENIED', `현재 상태(${current.status})에서 ${patch.status}(으)로 변경할 수 없습니다.`);
    }
    if (patch.status === 'SCHEDULED' && !patch.pickupSchedule.trim()) {
      throw new AppError(422, 'VALIDATION_ERROR', '반출예정 상태로 변경하려면 확정 반출 일정을 입력해야 합니다.');
    }
    saveUpdatedItem(itemId, patch, current.version + 1);
    insertStatusHistory({ applicationId: current.applicationId, itemId, actorRole: 'ADMIN', actorName: adminActor, before: current, after: patch });
    db.exec('COMMIT');
  } catch (err) {
    db.exec('ROLLBACK');
    throw err;
  }
}
```

## 3.6 비기능 요구사항 · 인수 검수 기준 · 리스크 대응

### 비기능 요구사항 목표
- **응답 성능**: 로컬/단일 VPS 기준 목록·상세·캘린더 조회 API `p95 ≤ 150ms`, 사진 5장 포함 신청 저장 `p95 ≤ 800ms`.
- **보안 및 프라이버시**: 업로드 JPEG 파일 내 GPS 태그 잔존 **0건**, 고객 응답 내 `admin_memo` 노출 **0건**, CSV 수식 실행 취약점 **0건**.
- **접근성 및 호환성**: 라이트·다크 양쪽 모두 본문·배지 명도 대비 **WCAG AA `4.5:1` 이상**, 최신 Chrome · Edge · iOS Safari · Samsung Internet 모바일(`390px`)·데스크톱(`1440px`) 무오류 렌더링.
- **무충돌 정적 검증**: `tsc -p tsconfig.server.json --noEmit` 및 `tsc -p tsconfig.client.json --noEmit` 경고·오류 **0건**.

### 필수 인수 테스트 시나리오 (검수 체크리스트)
1. **[무로그인 다품목 접수]** 비회원 상태에서 가구 2품목(소파 `상` + 식탁 `하-처분희망`)과 사진 3장을 첨부하고 4자리 PIN으로 신청 시 접수번호가 발급되고 단일 트랜잭션으로 저장된다.
2. **[중복 제출 방어]** 동일 `Idempotency-Key`로 신청 요청을 2회 연속 전송해도 DB에는 신청 1건만 생성되고 동일한 접수번호가 반환된다.
3. **[일정 가드레일]** `희망 반출일`을 `이사일`보다 늦은 날짜로 넣으면 클라이언트와 서버(`422`) 모두 접수를 거부한다.
4. **[사진 보안·GPS 제거]** GPS EXIF가 포함된 JPEG 업로드 시 저장된 파일에 APP1 GPS 메타데이터가 제거되고, `.exe`/`.html`을 `.jpg`로 이름만 바꾼 파일은 `415 UNSUPPORTED_MEDIA`로 차단된다.
5. **[비회원 PIN 조회 및 격리]** `/lookup`에서 올바른 연락처+PIN 입력 시 품목별 상태·마감일·반출일이 조회되며, 응답 JSON 어디에도 `admin_memo`가 없고 타인 사진 URL 직접 호출 시 `404`가 반환된다.
6. **[고객 초기 취소 가드]** 모든 품목이 `PENDING`일 때는 고객 취소가 성공하지만, 관리자가 1개 품목이라도 `IN_PROGRESS`로 바꾼 뒤에는 고객 취소 요청이 `409 TRANSITION_DENIED`로 거부된다.
7. **[회원 자동채움 & 비회원 건 승계]** 회원가입·로그인 후 `/apply` 진입 시 기본 주소가 자동 입력되며, `/my`에서 기존 비회원 신청 건(접수번호+PIN)을 내 계정으로 연결할 수 있다.
8. **[관리자 잠금 & 포털 쿠키 분리]** 관리자 로그인 5회 실패 시 `429` 잠금이 걸리며, 같은 브라우저에서 고객 로그아웃을 해도 관리자 세션(`fr_admin`)은 유지된다.
9. **[품목 처리 · 동시성 잠금 · 캘린더 반영]** 관리자가 소파는 `진행중(판매마감일 지정)`, 식탁은 `반출예정(확정 반출일시 지정)`으로 저장하면 `A-03` 일정 캘린더에 즉시 반영되고 `status_history`에 기록되며, 구버전 `version`으로 중복 저장 시도 시 `409 VERSION_CONFLICT`가 반환된다.
10. **[멀티 플랫폼 구동]** 모바일 뷰포트(`390×844`), 데스크톱 브라우저(`1440×900`), PWA 매니페스트 검증, Electron 래퍼(`desktop/main.cjs`) 창 로드가 콘솔 에러 0건으로 동작한다.

### 주요 리스크 및 기술적 대응
| 리스크 요인 | 영향 | 설계 반영 대응책 |
| --- | --- | --- |
| **폐쇄망·광고차단 환경에서 카카오 주소 스크립트 차단** | 고객이 주소를 입력하지 못해 신청 이탈 | 스크립트 타임아웃(2.5초) 또는 객체 미존재 감지 시 즉시 우편번호·기본주소 직접 입력 필드를 활성화(Graceful Fallback) |
